A stolen token should be worthless.

dpop-auth implements DPoP — Demonstration of Proof-of-Possession — for Node.js. Every access token is cryptographically bound to a private key on the user’s device, and every request carries a fresh, single-use proof. Steal the token, and you still can’t use it.

Why DPoP

Bearer tokens are the problem, not the solution.

The core flaw. A normal JWT is a bearer token: whoever holds it, owns the session. It authorises any machine, any script, any attacker that manages to copy it — from an XSS leak, a logged request, a compromised proxy, or a pasted token in a support ticket.

The DPoP model. Instead of “present the string,” dpop-auth demands “prove you own the key the token was issued to.” At login, the client generates an asymmetric key pair on the device and shares only the public key. The access token embeds that key’s thumbprint. Every request is then signed with the private key in a short-lived DPoP proof JWT — bound to the HTTP method, the URL, and a single-use ID.

What that buys you. Replayed tokens fail because proofs are one-shot (tracked in a memory or Redis replay store). Scrapers fail because no script can forge a signature from a private key it never had. Stolen tokens fail because the thief has the token but not the key. It is the same cryptographic idea behind hardware-backed WebAuthn, applied to API tokens.

How it works

Four steps, one bound session.

The whole flow is symmetric: the server package verifies what the browser generates, and the same device key protects the access token and the refresh token alike.

01

Generate device keys

At login, the browser generates an ES256 key pair with the WebCrypto API. The private key never leaves the device.

02

Issue a bound token

The server embeds the public key’s thumbprint (cnf/jkt) and an optional device fingerprint hash into the access and refresh tokens.

03

Sign every request

Each API call carries a DPoP proof JWT — signed by the private key, bound to the method, URL, and a unique single-use jti.

04

Verify & enforce

The Express middleware checks the signature, the binding, the timestamp window and the replay store — then lets the request through.

Features

Everything a sender-constrained API needs.

A complete toolkit — key generation, token issuance, proof verification, replay stores and middleware — in a package with a single runtime dependency.

cnf

Device-bound tokens

Access tokens carry a confirmation claim (cnf/jkt) tying them to a public key generated on the device. A token without its matching private key fails verification.

jwt

RFC-compliant DPoP proofs

Short-lived proof JWTs (typ dpop+jwt) signed per request with htm, htu, iat and jti claims — matching the DPoP draft specification.

jti

Anti-replay protection

Every proof carries a unique JTI tracked in a replay store — memory and Redis backends included — so the same proof can never be accepted twice.

fph

Anti-scraping layer

Scripts can’t replay a captured token: each request needs a fresh cryptographic signature from a private key the scraper never had.

#

Fingerprint binding

An optional device-fingerprint claim (fph), derived from user-agent, language, screen and timezone signals, adds a second layer on top of the cryptography.

mw

Express middleware & TypeScript

Drop-in middleware (plus optional-auth and requireDevice variants), a device-bound refresh flow, and full TypeScript definitions built in.

API surface

Batteries included.

A high-level DPoPAuth class ties the pieces together — createAuthFlow() issues the bound token pair, refreshAccessToken() renews them, and getMiddleware() returns configured Express middleware.

Main authentication middleware for Express routes.

Quick start

Protect a route in ten lines.

Config knobs: algorithm (ES256/RS256), expiresIn (default 300s), clockTolerance, maxAge for replay windows, issuer/audience, and enableFingerprinting.

01 Server — Express
import { dpopAuth, MemoryReplayStore } from 'dpop-auth';

app.use('/api/protected', dpopAuth({
  secret: process.env.DPOP_SECRET,
  algorithm: 'ES256',
  expiresIn: 300,
  enableFingerprinting: true,
  replayStore: new MemoryReplayStore(),
}));

app.get('/api/protected/data', (req, res) => {
  // req.token.sub — the user
  // req.thumbprint — the device
  res.json({ user: req.token.sub, device: req.thumbprint });
});
02 Client — Browser
// once, at login:
const { publicKeyJwk } = await generateDeviceKeys();

// on every request:
const proof = await createDPoPProof(
  method, url, devicePrivateKey, publicKeyJwk
);

await fetch(url, { headers: {
  'Authorization': `DPoP ${accessToken}`,
  'DPoP': proof,
}});
